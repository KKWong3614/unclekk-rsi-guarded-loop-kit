# 避坑清单 | Pitfalls（错误做法 → 后果 → 正确替代）

> 集中列出使用本包最常踩的坑。每条都来自真实测评反馈或实测返工，不是假想。
> 本文件是「反面教材集」：里面故意保留错误措辞作对照，因此不参与 `check_doc_numbers.py` 的数字/回避式校验；但它已登记在 SKILL.md 文档地图，不会成为孤岛文档。

## 一、数字与文档

| 错误做法 | 后果 | 正确替代 |
|---|---|---|
| 文档里手写自检数，脚本升级后不改 | 说明数字与实际对不上，测评反复扣分 | 写确切数字，并跑 `python3 scripts/check_doc_numbers.py` 全包守护（不一致 exit 1） |
| 把数字抹成「N/N」「以实跑为准」「跑脚本看输出」 | 测评判为「无法核对」，不进反退 | 写死确切值（如 `8/8`），CHANGELOG 历史段才允许旧数字 |
| 只改 SKILL.md 的数字，README / 各 references 漏改 | 少数步骤数字没同步，测评点名 | `check_doc_numbers.py` 默认校验全包 8 个活动文档 |
| 案例里的「真实输出」靠手写、不逐字复跑 | 实跑输出与文档差一个字（如 `'生产级可用'` 写成 `'生产级'`），测评判「示例与运行不符」 | 每个输出样例都实跑后照抄；改 linter 规则后重跑所有案例复核 |
| 把元工具 `check_doc_numbers.py` 加进 `test_all.py` 聚合 | AGGREGATE 自引用，每次改元工具都触发数字漂移 | 元工具独立于被测脚本，只校验、不进聚合 |
| 精简文档时删掉审计锚点（受众/审计报告样例/`**vX.Y.Z**` 标题） | spec_audit 从 18/18 掉分 | 精简保结构；锚点在 `unclekk-skill-spec` 的发布检查清单里列明 |

## 二、写回与护栏

| 错误做法 | 后果 | 正确替代 |
|---|---|---|
| 让脚本自动批准、自动写回生产技能 | 正是本包要拦的洗绿动作 | 只出候选骨架（`is_final_skill=false`），写回需人工授权 + 回滚路径 |
| 改任务集后自动重算哈希锁去迁就新任务集 | 门禁形同虚设，基线被悄悄替换 | 人工确认后显式重算；哈希不符一律 fail-closed |
| 把「改判据/白名单」当普通改动提交 | 判官链被污染，判定不可信 | IMMUTABLE 判官链零改动；绕过路径要显式留痕与授权 |

## 三、宣称与边界

| 错误做法 | 后果 | 正确替代 |
|---|---|---|
| 说「已实现 RSI」「四段闭环自动落地（严格）」「能力变强」 | 越过宣称边界，项目侧原型被写成严格完成态 | 说「方法论内核 + 项目侧原型 + 冻结基线回归未退化」 |
| 把 `PASS` / 全绿当成能力提升或语义达标 | 把回归尺误当能力尺 | `PASS` 只表示冻结基线未退化，方向靠独立指标 + 人工 |
| 文案里塞「100% 可靠」「显著提升」「生产级成熟方案」 | 隐性夸大，绕过关键词仍会被 linter 抓 | `python3 scripts/claim_lint.py <文件> --strict` 复核 |
| 在对外文案里直接抄「不可声称」章节的禁语 | 分不清引用和主张 | 用「不声称……」否定式；linter 有章节/否定/引号豁免 |

## 四、异常与输出

| 错误做法 | 后果 | 正确替代 |
|---|---|---|
| 输入结构错就让它裸崩（`AttributeError`/`TypeError`） | 判据崩溃被误读为「通过」，且用户看不懂 | fail-closed 返回友好提示 + 明确退出码（2=输入/输出错误） |
| 报告写不进去就静默成功 | 判定丢失还以为成功 | 捕获写入异常报 `[OUTPUT ERROR]` 并返回 2 |
| 任务集为空或结果缺项时默认放行 | 空尺子量出「全绿」 | 空集/缺项一律判回归退化，exit 1 |

## 五、触发与平台

| 错误做法 | 后果 | 正确替代 |
|---|---|---|
| 只在 `triggers` 写关键词就以为各平台都会加载 | 别的平台不自动触发，被判「装了没生效」 | 白话指令最可靠：「跑一遍四段闭环」「查退化没有」「这句话能不能说」 |
| 多个相近需求同时出现时随机选一条流 | 用泛泛 SOP 掩盖具体判定 | 按优先级：宣称边界 > 回归门禁 > 四段链 > 泛化咨询 |
| 把同 slug 升级当成新包发（换 slug/name） | 版本线分裂、用户找不到历史版本 | 同 slug 只递增 version；对外字段发布前经所有者确认 |
