# 宣称边界 | Claim boundary

> 「某句话能不能说」的权威对照。任何对外引用须同时带本文件与 SKILL.md 防误读声明。

## 判定三原则

一句宣称能否用，取决于三件事：**改进对象是什么、哪些环节是人工、PASS 怎么解释**。任一被模糊，就从诚实披露滑向幻影声明。

## 可声称（有支撑，须带限定）

| 措辞 | 限定条件 |
|---|---|
| 参考 RSIFlow 方法论内核的精简版 RSI 工具包 | 附可核对引文 arXiv:2610.21791v2 |
| 受护栏四段闭环 + bounded RSI 参考实现（项目侧原型）已落地 | 附证据，并同时保留下行「不可声称」 |
| 零依赖回归门禁 + 宣称边界 | 说明 `PASS = 回归未退化` |

## 不可声称（明令降级）

| 措辞 | 为什么不行 |
|---|---|
| 严格 RSI 完成态 / 已实现递归自我改进 | 本包是 bounded 项目侧原型，非严格完成态 |
| 四段闭环自动落地（严格）/ 全本地模型闭环达标 | 严格完成态未达成；全本地受本地硬件限制未达标 |
| 能力递归提升已被自证 / 全自主自我改进 | 方向裁决系统外，能力递归未被自证 |
| 技能能力变强 / 语义质量达标 | `PASS` 只证明冻结基线未退化，门禁不判方向 |
| 实时闭环已验证 / 已通过异族第三方复审 | 相关基线为离线；复审资格与实质结论是两回事 |

## 三条硬纪律

1. 对外引用任何数字，必须附「PASS = 回归未退化，非能力提升」，并区分示意值与实测值。
2. 禁止把「项目侧原型」写成「严格完成态」。`rsi` 作参照名词须带 bounded / 参考实现 / 项目侧原型 限定。
3. `guarded` 的含义必须讲清：受护栏、方向裁决系统外，非「已自主」。

## 常见误判

- 「门禁全绿所以改得更好」——错，全绿只说明没退化。
- 「有脚本所以闭环自动落地了」——错，脚本刻意不自动批准、不自动写回。
- 「去掉『精简版』更简洁」——错，删限定词即构成宣称风险（`claim_lint --strict` 会拦）。
